# Rental Housing Law Navigator

MIT AI Hackathon x RealPage (participant pack v5). Pick any sample building and see which
housing rules apply to it on a given date, with every answer traced to the exact sentence
of law it comes from.

**Not legal advice.** A prototype built from a fixed public corpus. Every answer shows its
as-of date, the source citation and the date the source was retrieved.

- **Module A, rule extraction:** an LLM reads the 54 corpus documents that have text and
  produces schema-valid rule records. Each record's quote is checked verbatim against the
  source document.
- **Module B, address lookup:** each of the 500 sample addresses is resolved to its legal
  state and city through the Census Geocoder, and each rule's coverage is tested with
  three-valued logic (`unknown` names the missing fact).
- **Module C, change tracking:** T1 to T5 run on any as-of date, with affected and
  conflict-flagged addresses.
- **Plain-language view:** one-sentence tenant and owner answers in English and Spanish,
  dropped whenever they state a number the quote doesn't contain.

How it works and its known gaps: [METHOD.md](METHOD.md). Decisions and open questions:
[NOTES.md](NOTES.md).

## Run

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate    macOS/Linux: source .venv/bin/activate
pip install -e ".[dev,llm]"

python -m navigator all        # ingest > chunk > extract > verify > geocode > lookups > changes
python -m navigator summaries  # plain-language answers (build time, cached)
python -m navigator eval       # self-evaluation; regenerates the Results block above
python -m pytest -q            # tests;  -m smoke = fail-closed checks, no network, no LLM
```

`make <target>` and `./run.ps1 <target>` (Windows) are thin wrappers with the same names.

LLM calls are cached in `cache/llm/` (committed), so the whole pipeline reruns offline with
identical output. A new extraction needs `ANTHROPIC_API_KEY`, set in the environment or in
`.env`. Geocoding calls the public Census Geocoder once; the results are stored in
`outputs/parcels.json`.

### Add a document (live extraction demo)

```bash
python -m navigator ingest-doc path/to/page.txt --jurisdiction "Hoboken, NJ"   # cached
python -m navigator rerun-live path/to/page.txt --jurisdiction "Hoboken, NJ"   # cache off for this doc
```

The file must use the corpus header (`SOURCE: <url>`, `RETRIEVED: YYYY-MM-DD HH:MM UTC`,
blank line). It is registered in `data/supplement/` and extracted, verified, looked up and
change-tracked. Unaffected rules keep their ids and bytes.

### API

```bash
python -m navigator api        # http://127.0.0.1:8000/docs
```

| Endpoint | What it returns |
|---|---|
| `GET /lookup?address_id=&as_of=&role=tenant\|owner&lang=en\|es` | the rights label: rows by category, with quote, citation, reasoning boundary and confidence |
| `POST /lookup` | the same, run live with facts the user enters (year built, units) |
| `GET /rule/{team_rule_id}` | the record, the source text window and the highlight offsets |
| `GET /search`, `GET /resolve` | address search; map click to the nearest sample address |
| `GET /timeline`, `GET /snapshots` | results across key dates |
| `GET /changes`, `GET /changes/{test_id}` | T1 to T5 with their checks and notes |
| `GET /audit?team_rule_id=` | the extraction and verify trail for one rule |
| `GET /eval` | the latest self-evaluation report |
| `POST /ingest` | add a document; streams progress as NDJSON |

The API serves precomputed JSON; only the deterministic engine runs per request. A missing
output gives 503, never an empty answer. Environment variables:
- `NAVIGATOR_CORS_ORIGINS`: deployed frontend origins, comma-separated.
- `NAVIGATOR_DISABLE_INGEST=1`: turns off `POST /ingest` on public deployments.

### Frontend

```bash
cd web
npm install
npm run dev          # syncs outputs/ into public/data, proxies /api to :8000
npm run build        # set VITE_API_BASE to the deployed API; without it, bundled data only
npm test && npm run typecheck && npm run check:no-law
```

If the API is unreachable, the app falls back to bundled data and says "Offline data".

## Architecture

```
data/starter/ (read-only pack) ─┐
data/supplement/ (added pages) ─┴─> ingest > chunk > extract (LLM, cached) > verify (gates, dates)
                                                                              │
data/sample_addresses.csv > geocode (Census) > parcels.json                   │ rules.json
                                       └───────────────> engine (coverage, precedence) <─┘
                                                           │            │
                                                lookups.json, timeline   changes (T1-T5)
                                                           │
                              summaries (LLM, guarded) > API (FastAPI) > web (React)
```

The LLM is used only in `navigator/extract/` (rules) and `navigator/explain/` (summaries),
at build time. Dates, jurisdiction resolution, coverage, precedence, explanations and change
tracking are plain Python with unit tests.

| Path | What |
|---|---|
| `navigator/ingest`, `extract`, `verify` | corpus to verified rule records |
| `navigator/geo`, `engine` | addresses to legal jurisdiction; coverage, precedence, explanations |
| `navigator/changes` | T1 to T5 matcher and trackers |
| `navigator/explain` | plain-language answers and their guards |
| `navigator/api` | FastAPI |
| `web/` | frontend (React, map, rights label, source drawer, date slider, changes page) |
| `eval/` | self-evaluation harness |
| `docs/CONTRACT.md` | exact formats and data facts (wins over the plans) |
| `CLAUDE.md`, `BACKEND_PLAN.md`, `FRONTEND_PLAN.md` | working rules and build plans |

## Scaling to a new jurisdiction

Add its official pages to `data/supplement/` (one page at a time, same header) and its Census
place to `config/jurisdictions.yaml`, then rerun the pipeline. No code changes.

*Not legal advice. Summaries of law here are for building a prototype.*
